## 三、三固化项

### 可玩性定义（意向文档 §4 M5 行验收② 的展开）

- **核心循环闭环：配置 → 观战 → 战报 → 再来**——玩家可为双方配置兵种构成与对局参数（预设 + 参数化），发起对局并观战至终局，读取战报（胜负 / 终局 tick / 双方存活），调参再来一局。
- **≥3 个预设挑战**终局可断言完成（挑战 = 构成/参数 + 期望终局判定的数据化定义；如以少胜多、克制极端例）。
- **胜率统计面为一等玩法**：批量采样（降规模口径 200 单位/局）出胜率矩阵/分布——复用 M0 实验场地基。
- **质量红线**：全程进程无 panic，自研 `game.*` 方法与游戏代码的错误路径不击穿进程；新增测试集任务全绿；同种子 + 同参数序列重放逐位一致（M0 红线延续，由测试驱动承担——BRP 按参数序列重放并逐位比对状态哈希）。
- **观战档验收**：万人常态 10k @60fps（帧采集口径沿万阵仓 T010 先例；**干净窗口纪律强制**——顺带关 M0 条件账 C-1，见 §六）。

### 体量上限

- **三重封顶（沿 M4 原值）**：系统 ≤10、日历周 ≤4、taskset 新增任务 ≤14（任务计在万阵仓 taskset）。
- **防失控条款**：任一触顶即触发范围复审，owner 明示裁决（返工 / 降标准留痕记入变更记录 / 终止），禁止默认放行（沿意向文档 §4 未达标处置口径）。

### 占位美术/音效来源策略

- **程序化优先，默认零外部资产**：六兵种 = 形状 × 阵营色程序化区分；HUD 用 bevy 内置默认字体。
- 补缺主源 **Kenney**（kenney.nl，官方 FAQ 明示 CC0——商用可用、无需署名，M4 已核）；备源 OpenGameArt（CC0 过滤器筛）/ freesound（许可混杂，逐件核后入库）。引入时 license 随包入库 + 万阵仓 `CREDITS.md` 记来源与许可。
- **音频非门槛**：缺省无声不阻塞验收（沿 M4 §五）。

## 五、game.* 方法面与宿主形态（诚实缺口补课）

- **形态**：万阵仓新增 bevy 宿主 bin——`RemotePlugin` + `RemoteHttpPlugin`（**仅回环 127.0.0.1**，沿意向文档硬约束「BRP 无鉴权、禁止绑定非回环」）；sim 核心**零 bevy 纯 lib 不动**（万阵仓纪律：模拟态确定性优先，bevy_ecs 调度序不入模拟路径——宿主只在外层调用 sim 公共 API）。
- **初始方法集**（≈6，随任务扩展）：
  - `game.deploy`（config：构成/参数/种子）→ 布阵快照哈希；
  - `game.run_to_tick`（n）→ 推进 n tick（观战模式下按帧率节流表现）；
  - `game.state_hash` → 当前状态哈希（断言锚）；
  - `game.outcome` → 终局四元组（胜负 / 终局 tick / 双方存活 / final_hash）；
  - `game.run_tests` → 套件判定面（pass/fail + 断言清单——**判定主体**）；
  - `game.screenshot` → 观战截屏（辅助证据）。
- **判定口径**（沿 pre-window T041 卡先例）：判定 = `game.run_tests` 返回的 pass/fail 字段 + taskset 断言清单逐条 + 状态哈希原文；agent 只作驱动，不作判定。
- **验证形态**：M5 期间 BRP 直调（curl/脚本）+ in-process 套件；T041 MCP 薄桥**保持冻结、按需解冻**（agent 驱动需求实证出现或 0.20 窗口开启再启——冻结出口「M0 后或 0.20 窗口」的 M0 分支已满足，解冻为主动决策非自动触发）。
