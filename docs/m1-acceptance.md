## 四、样本量与局限（必注明清单——引用本结论时逐条带出，不得只报 12/12）

1. N=12，**分列**：改码功能型 4/4、零改码核对型 7/7、测量型 1/1，合计 12/12=100%（断言 47/47）。
2. 阈值口径：>70%，N=12 时 ≥9/12，本批达标；任务不满足「独立同分布」假设，若引用置信区间须附此说明（12/12 单侧 95% 下界 ≈78%，改码子集 4/4 ≈47%——仅作样本量小的量化提示，非严格统计量）。
3. 任务定义者与被测执行者不同 agent，但**同属一个 AI 工作流体系**（同一 SKILL.md、同一批 brp-smoke 实测形态），非独立第三方基准；7 个核对型断言的被测行为已在 T003 首役预跑通过（11/11），存在重复验证成分——100% 不能外推为「该工作流在任意 Bevy 任务上的一次通过率」。
4. 改码任务体量局限：全部是 `game/src/sim.rs` 单插件内小改（TS-09/10 单文件，TS-02 含 cli/main），改动量 ±20~94 行，无新模块/新系统；结论不得外推到大改。
5. TS-11 的对照为 AutoVsync 组（基线锁 60.0，阈值 48）：只有相对 no-vync 基线 113.8fps 退化 >58% 才会报警，该格「通过」几乎不携带回归检测能力——升级窗口回归应改用 no-vsync 组基线（`docs/fps-baseline.md` 已有此建议）。
6. 一次通过判定点的非语义差异（如实带出）：TS-02 的「首次 check」测量点在最终一处纯空行编辑之前、断言用编辑后二进制（语义等价，单测为断言后补的 test-only 改动）；TS-10 在注释级行号修正后用最终二进制复跑 run2（与 run1 逐条一致）。
7. BRP 证据形态：多数断言为单点/双点采样；TS-11 的单点采样紧贴进程退出边界（退出前 0.19s）——只证明断言时刻的状态，不含「无回绕」证明。
8. entity id 跨进程不稳定（同 count/seed 下 index 0 的实体位串分别为 4294966884/4294966883/4294966882）：本批无断言依赖该稳定性；后续任务与升级窗口回归**不得断言绝对 entity id**（已写入 taskset README 回归口径注意事项）。
