## 分型定义（验证方式四型）

| 型 | 含义 | 验证动作 |
|---|---|---|
| 围栏 | 条目自带围栏断言，且所在文件已挂 doctest 门禁（当前仅 `bevy-dev/pitfalls.md`，接线 `docs/src/lib.rs`） | 围栏仍按标注行为执行（compile_fail 仍编译失败 / ignore 仍忽略 / 正例仍通过），doctest 门禁绿 |
| 行号锚 | 条目核心事实 = 本地源码行号（`xxx.rs:NNN` 出处） | 当前版本源码该行命中同一 API 形态；漂移则重锚并过门禁 |
| 探针 | 须运行时行为核实（BRP 调用 / 游戏进程观察 / driver 复跑） | 重跑条目记录的运行时验证，行为一致 |
| 计数 | 计数或留痕核对（claim-lint 断言 / 台账行 / 证据档存在性）；过程型条目（纪律/流程类）归此型 | 留痕可查、计数相符 |

## 使用说明（重核执行口径）

1. 重核按「期望结果」列逐条执行：**围栏**型随 doctest 门禁自动核（零人工）；**行号锚**型对照当前版本本地源码（cargo registry 路径或 `game/src/`）逐锚命中；**探针**型重跑对应 BRP / driver / 冒烟验证；**计数**型核台账与证据档留痕。
2. 漂移处置：行号漂移 → 重锚条目行号并过门禁；语义漂移（API 形态变化）→ 按错题纪律修订条目（最小复现 + 修复验证），版本窗口内完成；SKILL 面漂移 → 按其「已核实事实速查」纪律重锚并升版变更记录。
