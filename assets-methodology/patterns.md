### PAT-M-001：命令成败一律以真实退出码判定（REAL_EXIT 回显 + 后台轮询）

- 日期：2026-09-27
- 分型：模式（过程型；反例面见 [pitfalls.md](./pitfalls.md) PIT-M-001 根因②）
- 通用性分级：methodology
- 标签：`退出码` `门禁` `shell` `后台任务`

**场景**：一切命令式门禁与验证（编译、测试、构建、脚本驱动、进程收尾）——只要「命令失败必须被看见」。

**做法**：长时命令一律后台任务运行 + 轮询日志；判定不凭「有无输出 / 末行文字」，一律显式回显真实退出码：

```bash
cargo check --workspace > log 2>&1; echo "REAL_EXIT=$?"
```

必须用管道时（如取末行）显式取首命令退出码（`"${PIPESTATUS[0]}"`）或 `set -o pipefail`；证据日志以 REAL_EXIT 行收尾，自含判定。

**为什么**：POSIX 管道退出码取自末端命令，`cargo ... | tail` 的失败会被 tail 的 0 覆盖（PIT-M-001 实例：MSRV 拒绝险些被漏判）；「输出看起来正常」与「退出码为 0」是两个命题。

**验证证据**：T001 起门禁判定一律以真实退出码为准（PIT-M-001 修复②）；台账 21 行中 16 行以 REAL_EXIT 字面记录（T006–T017 全部与 T001/T002/T019/T021），其余五行（T003–T005/T018/T020）以「全绿」等文字转述（assets-methodology/task-ledger.md，2026-09-27 grep 复核）；示例：docs/evidence/m3-plan/gate-cargo-check-workspace.log 末行 `REAL_EXIT=0`。

### PAT-M-002：两阶段判定——人工对照先行，工具就绪后脚本断言重跑校准

- 日期：2026-09-27
- 分型：模式（过程型）
- 通用性分级：methodology
- 标签：`验收` `断言` `回归集` `测量口径`

**场景**：项目早期自动判定工具未就绪但验收测量不能等；或已有手工判定需统一升级为脚本口径。

**做法**：

1. 第一阶段：人工对照验收清单逐条判定，每条留命令 + 响应原文（raw 全文归档；摘录逐字回对 raw——PAT-M-006）；
2. 第二阶段（自动判定工具就绪后）：把清单转脚本断言（判定套件 / 驱动工具），对同批任务重跑校准；两阶段结果与口径差异记录在任务条目的判定记录内；
3. 第一阶段 raw 是第二阶段的语义基准：脚本断言复测的必须是当初人工判定的同一语义；口径升级（如抽样 → 全量比对）显式注明。

**为什么**：先测后自动化，保证「自动化断言断言的确实是当初的验收语义」；跳过第一阶段会在工具尚未可信时用不可靠判定污染台账测量。

**验证证据**：M1 12 任务两阶段闭环——第一阶段人工判定（T006..T017，47/47 断言）+ 第二阶段脚本重跑（78 断言 = 套件 33 去重 + 工具侧 45，12 任务退出码全 0；第一阶段 12/12 语义全部可复现）：docs/m1-acceptance.md §六 + docs/evidence/m1-phase2.md；12 个 taskset 文件判定记录两栏齐。

### PAT-M-003：字面值绑定断言——运行态读值必须 === 任务书字面值

- 日期：2026-09-27
- 分型：模式（过程型）
- 通用性分级：methodology
- 标签：`断言设计` `验收` `自洽性` `驱动工具`

**场景**：脚本化验收断言的设计与评审——尤其配置类验收（数量、种子、版本号、上限值）。

**做法**：驱动工具提供 `--expect-<field>` 字面值参数族；断言 = 「运行态读回值 === 任务书规定字面值」（严格相等），而非「读到 A 且 A 自洽」；正例退出 0 / 负例（错字面值）退出 1，负例须实测留痕。

**为什么**：仅断言内部自洽（如「回读 count 与启动参数一致」）不能发现「启动参数本身就错」——配置自洽 ≠ 配置正确；字面值绑定把任务书钉进断言链，负例实测证明绑定真的会失败。

**验证证据**：task-runner `--expect-count` / `--expect-seed`（T019）与 `--expect-max-speed` / `--expect-version`（T020）；负例（`--expect-seed 1`）REAL_EXIT=1 实测（T019，docs/evidence/m2-rpc.md 断言组）；TS-01 判定记录第二阶段。

### PAT-M-004：无净副作用套件——写通路断言内置「快照→写→断言→自恢复」

- 日期：2026-09-27
- 分型：模式（过程型）
- 通用性分级：methodology
- 标签：`测试套件` `状态注入` `回归集` `可重复性`

**场景**：验证「写通路」（注入 / 修改运行态状态）的自动化套件，且套件要进回归集被反复运行。

**做法**：套件内按「写前快照 → 写 → 读回断言 → 恢复 → 恢复后断言」闭环：快照须含可能被间接影响的组件 / 资源（如按 index 联动的打标组件）；恢复后断言关键计数 == 快照值；套件对世界状态的净效果为零，任意次连跑互不污染。

**为什么**：写通路验证天然改变世界状态，不自恢复则连跑互相污染、回归不可重复；恢复不完整会让后续套件假性失败（实例：批量实体套件恢复时丢打标组件，同进程连跑即假红——T020 返工④，审核轮 P1-3）。

**验证证据**：game 侧 11 个 run_tests 套件按「无净副作用」约定落地、12 任务连跑全绿（docs/evidence/m1-phase2.md）；ts-12 套件恢复含 `Option<Tagged>` 快照 + 恢复断言 Tagged=10==t0（T020 round2 实测）。

### PAT-M-005：常驻进程由后台任务托管 + 显式强杀与残留核对收尾

- 日期：2026-09-27
- 分型：模式（过程型；反例面见 PIT-M-007 / PIT-M-005）
- 通用性分级：methodology
- 标签：`进程生命周期` `后台任务` `收尾` `端口`

**场景**：验证流程依赖常驻进程（游戏 / 服务端）供外部工具交互；对任何「工具调用即进程组」的 agent 执行环境有效。

**做法**：

1. 常驻进程一律由长生命周期后台任务托管：整个驱动脚本作为一个后台任务运行（其 `&` 子进程随宿主存活），或常驻进程单独后台启动、判定调用随后独立执行；**严禁**在前台短命调用内 `&` 拉起（数秒内被回收）；
2. 启动后做存活快速失败（+2s 查进程表，早夭即判失败并带日志末行，不空耗就绪探测）；
3. 收尾：显式强杀 + 进程表残留核对（残留非零不得收工）；跨 shell 族调用原生命令注意开关转义（Git Bash 下 `taskkill //F`，PIT-M-005）。

**为什么**：前台调用按「调用结束即清理」管理其进程组，`&` 子进程不获豁免——进程「看起来启动成功、日志健康」但活不过几秒（PIT-M-007 实测）；杀不净则占用端口 / 资源，静默污染下一次验证。

**验证证据**：PIT-M-007 两形态实测对照（前台 `&` 数秒消失 vs 后台宿主下 11 个游戏子进程全存活至任务完成）；docs/evidence/m1-phase2/run-all.sh（每任务 taskkill + residue 核对全 clean）。

### PAT-M-006：证据摘录从 raw 直取，定稿前逐字回对

- 日期：2026-09-27
- 分型：模式（过程型；反例面见 PIT-M-004）
- 通用性分级：methodology
- 标签：`证据` `摘录` `raw` `誊写失真`

**场景**：把原始记录（响应 JSON、日志行、测量读数）摘录进成文文档 / 台账 / 断言脚本的任何环节。

**做法**：摘录一律从 raw 文件复制粘贴或脚本直取（机读优先于人肉转录）；定稿前对摘录逐字回对 raw（数值、单位、顺序、错误码）；发现失真按 raw 改正并加带日期勘误注，不静默改；审计方对成文证据做「全量数字扫描对回 raw」作为标准动作。

**为什么**：短时记忆对高熵数值只保留前缀印迹、末段以貌似合理值填充（PIT-M-004 两例 + T013 执行中自查一例，高频人因失误）；机读（脚本从 raw 抽值）从根上消除该环节。

**验证证据**：PIT-M-004（M1 审计全量数字扫描发现 2 例 + 勘误落实后复扫一致）；taskset/README.md 公共前置固化「摘录必须逐字回对 raw 原文后才可定稿」；T013 证据文件自查改正一例（台账 T013 工具级偏差①）。

### PAT-M-007：驱动脚本绝对路径锚定 + 落位前置自检

- 日期：2026-09-27
- 分型：模式（过程型；反例面见 PIT-M-006）
- 通用性分级：methodology
- 标签：`脚本` `路径锚定` `CWD` `驱动`

**场景**：任何按自身位置定位仓库 / 工程根的批处理脚本（重跑驱动、证据采集、构建编排）。

**做法**：锚定两步走——先取脚本真实目录再上溯固定层级，不依赖调用方 CWD：

```bash
SCRIPT_DIR=$(cd -- "$(dirname -- "$0")" && pwd)
REPO=$(cd -- "$SCRIPT_DIR/../../.." && pwd)
```

此后所有路径一律 `$REPO/...` 绝对引用；锚定后立即做一次可观测前置自检（如在目标证据目录建 summary 前置文件），首行失败当场暴露。

**为什么**：按直觉写上溯层级差一即全盘落错目录，且重定向把报错吞进错误目录、控制台「看起来正常」（PIT-M-006 实例：11 任务产物全落杂散树、游戏从未启动）；前置自检把锚定错误提前到第 1 秒。

**验证证据**：docs/evidence/m1-phase2/run-all.sh（绝对锚定版，12 任务产物落位正确）；PIT-M-006（首版相对锚定失败的 bash -x 复现存档 pit-m006-repro.txt）。
