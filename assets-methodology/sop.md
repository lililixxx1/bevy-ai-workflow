# 方法论层 SOP（三条工作流操作手册）

> 状态：**实战回填 v1**（2026-09-27，M3 Block B——操作步骤自 M1/M2 实战提炼；骨架期条目的语义未变）。
> 本层引擎无关，任何「编译器 + 运行时反馈」栈可带走（意向文档 §6）；引擎 / 版本特定细节一律指向 `bevy-dev/SKILL.md`，此处不重复，仅以「本项目实例」括注锚定。

## 工作流一：AI 写文档（知识生产）

- 产出落点：`docs/`（经薄封装纳入文档示例编译门禁；本项目实例：`include_str!` → `cargo test --doc -p docs`，意向文档 §5.1）。
- 门禁：文档示例门禁通过才可合并；长运行示例标 `no_run` 并注明理由，禁止无理由 `ignore`。
- 版本标注：文档一律标注适用的引擎版本号；版本升级时对照官方 migration guide 批量修订后重过门禁。
- 操作步骤（M1/M2 实战提炼，2026-09-27）：
  1. **写前定规范**：按文档写法基准执行（本项目实例：`docs/doc-conventions.md`——版本标注 / 示例默认真实可测 / no_run 附理由）。
  2. **接入门禁**：新文档必须同步接入门禁封装（本项目实例：`docs/src/lib.rs` 追加 `#[doc = include_str!(...)]` 空模块）——未接线即未入门禁。
  3. **示例分级**：纯逻辑断言直接可测；需窗口 / GPU / 长运行的标 `no_run` + 理由；语义上无法用编译断言的标 `ignore` + 理由。
  4. **过门禁**：以真实退出码判定（PAT-M-001）；失败即修，禁止带错提交。
  5. **证据与摘录**：运行证据归档证据目录（本项目 `docs/evidence/`）；从 raw 摘录进文档的内容定稿前逐字回对（PAT-M-006）。
  6. **收尾**：文档变更与相关代码同提交；台账登记；行为 / 接口 / 版本相关变更核对文档同步义务（§六仓库纪律）。

## 工作流二：AI 写代码（受 skill 约束）

- 纪律：禁凭训练记忆写引擎 API，不确定必须查对应版本源码 / 文档 / 官方示例（意向文档 §5.2）；每次代码变更必须过编译门禁；涉及运行时行为必须走工作流三验证。
- 约束来源：引擎特定层 skill（本项目为 `bevy-dev/SKILL.md`）+ 本 SOP。
- 操作步骤（M1/M2 实战提炼，2026-09-27）：
  1. **开场核对**：读 skill 的开场清单（版本锁 / 工具链 MSRV / 台账无缺位），缺一先补再开工（本项目实例：SKILL.md §0）。
  2. **查证先行**：不确定的 API 按 skill 的查证优先级核实（本地依赖源码 > 精确版本文档 > 官方示例；本项目实例：SKILL.md §2.1）；写码处注释留痕（出处 + 核实日期）；「已核实 ≠ 已验证」——写进工程并过编译才算已验证（SKILL.md §2.3）。
  3. **写码**：按 skill 架构约定组织（模块 / 插件 / system 拆分；本项目实例：SKILL.md §3）；任务书或种子信息与源码冲突时以源码为准并记台账。
  4. **编译门禁**：全 workspace 编译检查，真实退出码判定（PAT-M-001；本项目实例：`cargo check --workspace`，SKILL.md §4.1）；长时命令后台跑 + 轮询。
  5. **运行时行为 → 工作流三闭环**：只凭编译通过不得收工（意向文档硬约束 3）。
  6. **踩坑回写**：同一任务收尾前回写错题本（通用性分级判定落点）+ 模式入库（过门禁才入）+ 台账登记；过程型做法固化为 PAT-M 时验证证据指向实际执行任务（pitfalls-schema.md 分型补充）。

## 工作流三：AI 操控运行中的游戏（验证闭环）

- 技术底座：引擎 / 框架的远程操控通路常驻（本项目实例：bevy_remote BRP；通用桥复用 bevy_brp_mcp、不自建——意向文档 §5.3 已定案）。
- 安全约束：远程操控通路**仅监听回环地址（127.0.0.1）**，禁止绑定 0.0.0.0 或局域网地址——无鉴权通路暴露即等于交出操控权。
- 验证取向：状态注入断言优先，截图作辅助证据（意向文档 §3 学界结论）。
- 操作步骤（M2 后成熟形态，2026-09-27）：
  1. **启动**：release 构建 + **后台任务托管**常驻进程（PAT-M-005——前台短命调用内 `&` 起的子进程数秒被回收）；轮询就绪（日志 / 端口探活）。
  2. **冒烟**：先用无参方法确认通路活着（本项目实例：`rpc.discover`），再发业务请求。
  3. **断言设计**：状态注入 + 数学复算优先（参考值独立复算，不抄被测方输出）；请求 / 响应形态先查源码或实测，不凭记忆猜；「必须存在」的引用用严格模式让未知显式报错而非静默空结果。
  4. **自动判定**：优先自研判定套件（本项目实例：`game.run_tests`，无净副作用约定 PAT-M-004）+ 驱动工具字面值绑定（PAT-M-003）；无套件时逐条断言，原始响应全文归档。
  5. **收尾**：显式杀进程 + 进程表残留核对（残留非零不得收工；跨 shell 族开关转义见 PIT-M-005）；证据（请求 / 响应原文、真实退出码、日志）归档证据目录；台账登记。
  6. **判定记录**：任务测试集条目内按两阶段判定记录填写（PAT-M-002）。

## 回写纪律（每次任务收尾）

1. 踩坑回写错题本：同一任务收尾前、最迟下次会话开始前；分级判定与条目模板见 [pitfalls-schema.md](./pitfalls-schema.md)。
2. 台账登记：见 [task-ledger.md](./task-ledger.md)。
3. 行为/接口/版本相关变更同步更新 `docs/` 或模式库；纯重构、格式化、补丁版本升级豁免（§6 仓库纪律）。
4. 过程型做法固化：已在任务中执行并留痕的流程 / 断言设计做法可入 `patterns.md`（PAT-M-*），验证证据指向实际执行过的任务与留痕（见 pitfalls-schema.md 分型补充）。
