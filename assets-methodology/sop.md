# 方法论层 SOP（骨架）

> 状态：**骨架**。三条工作流的操作步骤在对应工作流首次实战后充实（M1 起）。
> 本层引擎无关，任何「编译器 + 运行时反馈」栈可带走（意向文档 §6）。

## 工作流一：AI 写文档（知识生产）

- 产出落点：`docs/`（经 `include_str!` 薄封装纳入 doctest 门禁）。
- 门禁：`cargo test --doc -p docs` 通过才可合并；长运行示例标 `no_run` 并注明理由，禁止无理由 `ignore`（§5.1）。
- 版本标注：文档一律标注适用 Bevy 版本号；升级时对照 migration guide 批量修订后重过 doctest。
- 操作步骤：（待 M1 实战后回填）

## 工作流二：AI 写代码（受 skill 约束）

- 纪律：禁凭训练记忆写 Bevy API，不确定必须查 docs.rs 对应版本或官方 examples（§5.2）；每次代码变更必须过 `cargo check`；涉及运行时行为必须走工作流三验证。
- 约束来源：`bevy-dev/SKILL.md` + 本 SOP。
- 操作步骤：（待 M1 实战后回填）

## 工作流三：AI 操控 Bevy（验证闭环）

- 技术底座：`bevy_remote`（BRP）常驻游戏 + bevy_brp_mcp 桥（复用，不自建通用桥）（§5.3）。
- 安全约束：**BRP 仅监听 127.0.0.1**，禁止绑定 `0.0.0.0` 或局域网地址。
- 验证取向：状态注入断言优先，截图作辅助证据（§3 学界结论）。
- 操作步骤：（待 M2 实战后回填）

## 回写纪律（每次任务收尾）

1. 踩坑回写错题本：同一任务收尾前、最迟下次会话开始前；分级判定与条目模板见 [pitfalls-schema.md](./pitfalls-schema.md)。
2. 台账登记：见 [task-ledger.md](./task-ledger.md)。
3. 行为/接口/版本相关变更同步更新 `docs/` 或模式库；纯重构、格式化、补丁版本升级豁免（§6 仓库纪律）。
