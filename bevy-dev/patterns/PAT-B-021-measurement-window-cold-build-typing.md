# PAT-B-021-measurement-window-cold-build-typing

### PAT-B-021：量测窗口空闲独占 + 冷编分型授权——负载敏感门禁的机器可验放行依据

- 日期：2026-10-07（跨仓回流：万阵试金石仓，owner C1 拍板随线动作）
- 适用版本：bevy 0.19.1（万阵仓同锁版本实测；形态依赖 bevy 依赖树冷编足迹与 doctest 拉起 rustc 的负载特性）
- 分型：模式（**过程型**——流程/纪律类做法，无可编译代码载体；门禁 = ≥1 任务实际执行并留痕〔pitfalls-schema.md 过程型条款，2026-09-27〕，留痕在万阵试金石仓，本条目只引路径不复制正文）
- 通用性分级：bevy-specific（录入理由：冷编足迹/门禁负载特性随 bevy 依赖树与工具链；「负载敏感判定不可信」原则面引擎无关，机制面见万阵仓）
- 标签：`量测窗口` `冷编` `分型授权` `commit余量预检` `负载敏感` `-j1`
- 源码出处：无本仓代码载体——执行依据 = 万阵仓 AGENTS.md 常用命令节（预检命令与 -j 上限）+ task-ledger.md T010/T019/T022/T024 行（授权裁决逐单留痕）

**场景**：bevy 项目的性能量测（帧率/耗时/吞吐判定）、release 冷编、doctest 门禁——一切对机器负载敏感、结果会随并发漂移的构建与量测动作；以及低内存余量时段是否放行重型构建的裁决。

**做法**：① **量测/doctest 类门禁机器空闲独占**——开跑前声明当前无其他负载；共享负载下的红/绿均不可信，**失败集合逐轮漂移 = 环境抖动签名**（非代码回归；本仓 PIT-M-011 同源）；② **冷编分型授权**：release 构建前置 **commit 余量预检**（`Get-CimInstance Win32_OperatingSystem` 读 CommitFree/CommitLimit，判定式 = 余量 ≥ 在飞足迹 + 预估 + 地板）；余量不足时按**冷编签名分型**——签名命中（指纹口径 = 档存测量件，非位级）即真冷编，可授权**降并行放行**（`-j 1` 峰值约减半）+ 内存监控地板（如 7G），签名不匹配即中止上报；③ 构建非位级可复现如实上报、不做位级宣称；④ cargo 并行度全局上限（`-j 3`）且门禁**串行**执行——并发多 cargo 假失败先例在档。

**为什么**：bevy full 冷编是时间/内存重型操作（万阵 T010 实测单次 ≈19m45s、依赖重型足迹使固定余量口径在低余量时段不可用）；量测判定对并发负载极敏感（万阵 T012 带载复测帧率漂移 -79%~-89%、跨样本不可复现——只能作条件账挂起待干净窗口复测）；分型授权让「降并行放行」有机器可验依据（冷编签名）而非临场拍板，签名不匹配宁可中止。

**验证证据**（全部在万阵试金石仓，跨仓引用不复制正文）：

- 带载不可复现 → 条件账：docs/evidence/m0/review/report.md（T012 P1-1，-79%~-89% 漂移三样本）
- 冷编签名中止机制实效 + `-j 1` 放行：task-ledger.md T019 行（真冷编确认、12G 口径不适用低余量、-j1 峰值减半 + 7G 监控地板）
