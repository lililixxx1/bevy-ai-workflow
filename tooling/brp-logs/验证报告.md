### 1.1 与旧版资料的关键差异（0.19.1 实测口径）

以下三条均以 0.19.1 本地源码 + 实测响应双重核实，写入结论时不得引用 0.16 时代的资料：

1. **Vec3 的 BRP 序列化形态是数组**。spawn 时 `origin: {x,y,z}` 报错
   `"game::sim::Velocity is invalid: invalid type: map, expected a sequence of 3 f32 values"`（04 文件原文）；
   读回时同样是 `[1.0,2.0,3.0]` 形式（06 文件）。
2. **`world.list_components` 必须指定 entity**（`BrpListComponentsParams{entity}`，`builtin_methods.rs:277-280`）。
   传 `{}` 直接 `missing field 'entity'`（07 文件原文）。要全量类型清单用 `registry.schema` 无参数调用。
3. **`world.mutate_components` 是字段级单点改写**（`BrpMutateComponentsParams{entity, component, path, value}`，
   `builtin_methods.rs:286-302`），不是旧资料的整组件 map 覆盖。改 `Wanderer.index` 用 `path:"index"`。

### 1.2 反射注册依赖的验证（种子信息第 3 条复核）

`world.list_components`（带 entity）返回 `["game::sim::Velocity","game::sim::Wanderer"]`（07 文件）——
恰为 `game/src/sim.rs:90-91` 显式 `register_type` 的两个 Component；Resource 侧 `SimStats` 可经
`world.get_resources` 读取且 `tick` 字段持续增长（08 文件两次采样 tick=13968…）。结论：**BRP 操作组件确实依赖
反射注册，种子信息属实**；`registry.schema`（`with_crates:["game"]`）返回 5 个 game 类型（含 `game::camera::CameraRig`，
`game/src/camera.rs` 也注册了）+ 37 个无 crate 名的原语/内建类型——后者因 BRP 侧过滤逻辑只作用于**有** crate 名的类型
（`builtin_methods.rs:1682` 的 `if let Some(crate_name)` 分支，核实 2026-09-26），无 crate 名者全部放行，共 42 个（02 文件）。

### 1.3 附带发现：registry.schema 的 with_crates 过滤会放行无 crate 名类型

42 = 5（game::）+ 37（`()`, `(u16,u16)`, `[u8; 4]`, `bool`, `u16` 等原语/内建）。做「只看我游戏类型」断言时须客户端侧
再按前缀 `game::` 过滤，不能信 `with_crates` 的排他性。

## 二、bevy_brp_mcp 兼容性实测（任务第 3 条）

- 上游溯源：任务给的 `github.com/natepiano/bevy_brp_mcp` 克隆成功，但仓库已**归档**（ARCHIVE_NOTICE.md：迁移至
  `natepiano/bevy_brp` workspace，crate 仍在 crates.io 发布）。crates.io 实查最新 0.22.7（2026-09-23 发布），
  其依赖为 `bevy ^0.19.1`（crates.io dependencies API）——与本仓库锁定的 bevy 版本一致，故选它实测。
- 安装：`cargo install bevy_brp_mcp --version 0.22.7 --locked`（编译 7m05s）。
- 驱动：MCP stdio 探针三轮会话（initialize → tools/list → tools/call 覆盖 19 个测试场景、共 32 次调用），全量请求/响应原文存
  `10-mcp-session{,2,3}-transcript.jsonl` + `.summary.json`；逐工具结论见 **`11-mcp-tools-report.md`**。

**结论：协议级兼容。** 47 个工具中三轮会话共发起 32 次 `tools/call`：19 次成功（含
spawn/query/mutate/get/list/despawn、resources 读写、registry_schema、brp_execute 逃生舱、
type_guide）；13 次失败无一为协议不兼容——8 次为我方探针参数格式错误（被 MCP 参数校验正确拦截）、
2 次为故意的错误处理探针（错误码与原文干净透传）、3 次为游戏未装 `bevy_brp_extras` 的环境性预期
失败（报错原文自解释）。按原始调用次数的逐条统计见 11 号报告「按原始调用次数统计」节。
MCP 对 0.19 的三处 schema 收紧（§1.1）均已正确适配。无任何协议不兼容发现。

使用注意（详见 11 号报告）：`world_query` 大结果只回计数元数据，全量行需 curl 直连；
extras 系 14 个工具（screenshot/send_keys/…）需游戏侧加装 `bevy_brp_extras`。

## 三、结论与后续

1. **任务第 1 条（通路）**：release 游戏 BRP 常驻通路验证通过——启动后约 1 秒就绪，9 个内置方法
   （含任务点名的 world.query / world.spawn_entity / world.mutate_components / registry.schema）全部实测成功，
   每个方法的请求与响应原文存证入库（01–09 文件）。
2. **任务第 2 条（存证）**：完成，含失败重试对照（04/07/08 文件的失败原文与修正后成功原文）。
3. **任务第 3 条（bevy_brp_mcp）**：完成，`11-mcp-tools-report.md`；结论 = 兼容（0.22.7 ↔ bevy 0.19.1）。
4. **种子信息复核**（任务书三条全部落实）：
   - 默认监听 127.0.0.1:15702 ✅（http.rs:52,60）；插件与 with_method 形态 ✅（种子信息中
     `RemotePlugin::with_method` 在 0.19.1 实为私有 fn，公开 API 为 `with_method_main`/`with_method_render`，
     lib.rs:591-611——与 T002 查证一致，本任务未用自定义方法，未受影响）；
   - 内置方法清单 ✅（rpc.discover 实测 23 个，与 builtin_methods.rs 常量数一致）；
   - **BRP 依赖反射注册 ✅**（§1.2：register_type 的类型可查可改，registry.schema 过滤行为记录在案）。
   - Hotpatching：本任务未涉及（不在任务书四条之内，未测，不虚报）。
5. **对工作流三的落地意义**：AI 操控运行中游戏的通路成立。优先用 bevy_brp_mcp（schema 已适配 0.19，
   错误透传干净），全量数据导出用 curl 直连；后续若需截图/输入注入，评估给 game 加 `bevy_brp_extras`。
6. **知识回写**：新增错题 PIT-B-004（params 存在性语义 + 单数 resource 字段，bevy-dev/pitfalls.md）；
   模式候选 PAT-B-002（BRP 验证闭环的标准动作序列）因「正例须过编译+运行验证」门禁——本任务的探针脚本
   为一次性工具未入库，该模式暂缓入库，待工作流三正式化时再补（诚实记录，不凑数）。
